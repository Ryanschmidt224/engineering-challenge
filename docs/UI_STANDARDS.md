# Current UI standards

Shared rules belong to a component or token owner and apply across Projects, Workshop, Lessons Learned and settings. Avoid a page-specific override when the shared component is responsible.

- `theme.css` owns semantic colors, spacing, type, control dimensions and breakpoints. Use those tokens rather than literal fallback colors.
- `ui-kit.css` and `BSUI` own framed buttons, quiet actions, paired label/value fields, disclosure sections, section-header edits and status feedback. `.button` and `.ui-button` share the same definition; they are not separate visual systems.
- Projects and Lessons Learned editors share `.ui-editor-group` section bands and `.ui-editor-fields` compact field rows, using the same bordered `.field` controls. Labels sit beside bounded inputs on wide screens and stack on phones. Keep related controls close, with usable touch targets. Do not use percentage-wide empty label columns.
- Disclosure sections default closed unless the workflow needs immediate input. Section edits belong in the expanded header; creation actions belong in the body. Keep save/upload feedback close to the owning action. An idle lesson has no success banner or reserved empty strip. Lessons autosave shows pending/error feedback beside Done while editing, with retry/conflict controls, without rebuilding or moving the typing fields.
- Tree labels put part number before name, share the navigation selection treatment and show assembly connectors. Reordering and drag operations use guarded current commands, retaining revision/history behavior.
- Project summaries, parts and subassemblies use the ordered photo gallery. Photo 1 is main; returning to a page starts the viewer at 1. Drag/drop and accessible earlier/later actions change order. Build controls stay in the identity frame above the separate photo frame. Viewer filenames/instructions are omitted; library names and captions remain editable. Reordering shows immediate progress, retains the confirmed order until accepted and reuses thumbnail nodes after confirmation; it does not reload the whole project just to show a new order.
- Photo editing uses a prominent primary Done button and normal-flow tools. Workshop retains a single cover; lesson steps share upload/paste/progress controls without a main slot. Existing standalone project pictures remain readable and adopt into the gallery without reupload. Choose files, drag/drop and image paste share native selection helpers; persistence stays with the owning feature. Pending previews remain visibly unsaved, and refresh failure after a committed save must not imply that the save failed.
- Saved Workshop products have a visible Photos section in view and edit mode. Add photo opens the shared choose/drop/paste controls; photos save immediately without saving or discarding other product edits. Upload retries reuse their identity, and a failed refresh offers refresh rather than reuploading confirmed photos. Archived products and families retain their photos without upload controls.
- Rich HTML is not accepted as ordinary user content. Use text nodes for names, descriptions, records and Lessons Learned. Keep focus, keyboard access, dialog dismissal and native file behavior tested.

Current page layout owners are `project-workspace.css`, `family-workshop.css`, `knowledge.css`, `project-directory.css`, `photo-controls.css` and the shared kit. The previous `site*.css` cascade and old project renderers are retired. See [CSS_INVENTORY.md](CSS_INVENTORY.md) for current measurements.

## Action confirmations

Archive, restore, discard, guarded save actions and permanent project deletion use `BSConfirmation` (`confirmation-dialog.js` and `.css`). The shared frame centers in the viewport, gives the title a muted band, contains readable consequences, and puts Cancel before the action in a separated footer. Cancel starts focused for confirmations. Prompt inputs may receive focus for entry. Permanent project deletion retains typed-name admission, operation identity, retry behavior and red action styling. General edit forms and full-screen photo viewers retain their layouts; browser-generated unload warnings remain browser-owned.

Workshop product identity and specifications use compact, content-height read rows with shaded section bands and labels beside bordered values. Small AI source disclosures sit at the right of a value; opening one reveals the full source, conditions and document evidence. Long values wrap and phone layouts stack labels without clipping content.
