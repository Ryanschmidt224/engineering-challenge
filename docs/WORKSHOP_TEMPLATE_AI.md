# Template-scoped product lookup

Find with AI is between Product identity and Specifications. It requests only fields selected from the current template (visible fields; project-use fields when their toggle is shown). The backend reads those field IDs/revision from D1, rejects foreign/stale fields before a paid lookup, and filters provider results back to those exact template terms. Unverified values stay absent; no representative ratings from another manufacturer/package are requested. Existing compatible-unit/type/condition and explicit replacement rules remain.

An AI result must contain product name, manufacturer, exact manufacturer part number and an HTTPS supplier URL. Incomplete identity is rejected. Applying results requires those fields in the resulting draft, and an AI-assisted draft cannot save after clearing them. Manual product entry is still allowed. Suggestions never automatically save a product, add template fields or modify a project copy.

The optional technical-document control uses the shared file/drop/image-paste surface. It accepts a PDF, UTF-8 text/CSV, PNG, JPEG or WebP up to 5 MB. New files remain local until Save product, then upload through the normal Workshop attachment endpoint. A failed upload retains its pending file and the now-saved product revision for retry. Cancel/discard clears the pending selection. A saved file can be explicitly selected as a source on later edits; the server checks its product ownership before reading R2. No server-side fetching of arbitrary document URLs.

PDFs use Responses API input_file with a base64 data URL; text and images use their corresponding content inputs. Official input format: https://developers.openai.com/api/docs/guides/file-inputs. Documents are untrusted source data, not instructions. Changing identity or the selected source invalidates outstanding results. Existing API model, owner/origin/enable checks, quota and spending controls are retained; no automatic lookups or paid test calls.

Validation covers template filtering and request contents, required identity/supplier, PDF payload construction, document persistence/exact bytes, saved-document reuse, drop/paste, upload failure/retry, unit/condition preservation and stale-result handling. Existing generic lookup callers retain their compatibility contract.
